# 国际化维护说明

界面使用 i18next + react-i18next。文案位于 `src/i18n/locales/*.json`，组件通过 `useLocale()` 获取 `t`、数字格式化和诊断翻译接口；不要在组件中判断某一种语言，也不要将多种语言作为函数参数传入。

## 增加语言

1. 在 `src/i18n/locales` 新建以 BCP 47 语言标签命名的 JSON 文件，例如 `fr.json` 或 `pt-BR.json`。
2. 填写 `label`（该语言的自称）、`direction`（`ltr` 或 `rtl`）和 `messages`。以现有资源作为键名与插值参数参考。
3. 翻译完整句子，保留插值参数；按目标语言的复数类别添加 `_one`、`_other` 等键。不要把数量与句子片段在 JSX 中拼接。
4. 执行类型检查、单元测试和相关浏览器测试，检查长文案、地图与移动布局。`dir` 会同步到文档；新增从右到左语言仍需单独验收布局。

Vite 自动发现这些文件，语言选择器自动列出它们，无须修改组件、语言联合类型或条件分支。当前资源较小，随应用打包；没有翻译服务或后端依赖。

`en.json` 定义消息键的 TypeScript 类型及默认回退文案。增加新功能时先在该文件添加语义明确、稳定的键；现有键不应因改写文案而改名。其他语言可以逐步补齐，缺失键回退到英文。单元测试检查已有翻译的键名和插值参数，并验证第三种语言及回退机制。

## 选择与格式化

语言偏好按本地已选值、浏览器语言列表依次匹配，先精确匹配地区标签，再匹配基础语言，最后回退到英文。选择保存在 `localStorage`；不可用时仍能切换，但不保证下次访问保持选择。文档 `lang` 和 `dir` 随选择更新。

数量使用 i18next `count` 选择复数形式；`{{count, number}}` 和 `useLocale().number()` 使用当前语言的数字格式。距离显示与计量单位不改变核心计算单位。插值内容由 React 转义，不使用 HTML 翻译或 `dangerouslySetInnerHTML`。

## 处理数据与诊断

预处理提示和导入警告只携带 `code + params`，在界面层翻译。新增诊断时同时提供 `issues.CODE` 正文和 `issues.title.CODE` 标题，界面不直接展示英文错误码。报告保留完整的诊断记录，并附上当前语言的解释。

`src/i18n/diagnostics.ts` 兼容旧草稿中的英文诊断，恢复可识别的数量、缺口长度和站点名称后重新翻译；缺少必要参数时使用本地化标题，避免显示未替换的占位符。未知诊断和底层异常可保留原文作为回退。

源文件中的路线名称、站点名称和用户编辑的文字属于数据，不随语言切换重写。切换语言不重新生成路线身份，也不改变 RTE 字节或 revision；浏览器测试验证这一约束。

参考：[i18next 配置](https://www.i18next.com/overview/configuration-options)、[复数规则](https://www.i18next.com/translation-function/plurals)、[React 翻译 Hook](https://react.i18next.com/latest/usetranslation-hook)。
